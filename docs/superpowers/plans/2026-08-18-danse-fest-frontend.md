# DanseFest Frontend — план реалізації

> **Для агентів:** ОБОВ'ЯЗКОВИЙ САБ-СКІЛ: використовуй `superpowers:subagent-driven-development` (рекомендовано) або `superpowers:executing-plans`, щоб виконувати план задача за задачею. Кроки позначені чекбоксами (`- [ ]`).

**Мета:** Побудувати інтерфейси ядра змагання — реєстрацію з ростером, налаштування конкурсу, конструктор програми, кабінет судді й результати.

**Архітектура:** React 19 + react-router. Кожен модуль бекенду має свій файл-клієнт у `src/lib/` за наявним зразком (`lib/nominations.ts`: типізовані інтерфейси, `request<T>`, клас помилки `XxxApiError`). Сторінки в `src/pages/`, багаторазові частини в `src/components/`. Стилі — CSS-модулі поруч із компонентом. Жодної арифметики часу, кворуму чи місць на клієнті: усе рахує сервер, клієнт лише показує.

**Стек:** React 19, react-router-dom 7, TypeScript, Vite 8, CSS Modules, `fetch`. Тести — Vitest + @testing-library/react (додаються в Task 1).

**Spec:** `docs/superpowers/specs/2026-08-18-danse-fest-technical-vision-design.md`
**Парний план:** `docs/superpowers/plans/2026-08-18-danse-fest-backend.md` — усі ендпоінти, на які тут посилаюсь, визначені там.

## Глобальні обмеження

- Мова інтерфейсу — **українська**. Жодного англомовного тексту в UI.
- Base URL береться з `src/lib/api.ts` (`API_BASE_URL`), ніколи не хардкодиться в компоненті.
- Кожен клієнт у `src/lib/` повторює наявний зразок: експортовані інтерфейси,
  `authHeaders()`, `extractMessage()`, `request<T>()`, окремий клас помилки.
- Кожен екран із завантаженням даних має **три стани**: завантаження, помилка з
  кнопкою «Спробувати ще раз», порожній стан з поясненням що робити далі.
- Кнопки, що шлють запит, блокуються на час запиту й показують текст стану
  («Зберігаємо…»), інакше подвійний клік створює дублікат.
- Помилки з сервера показуються **дослівно** — бекенд віддає готові українські
  повідомлення, вигадувати свої не треба.
- Час показується як `ГГ:ХХ:СС` (у програмі) або `ГГ:ХХ` (час старту відділення).
  Тривалості — `Х:ХХ`. Форматування — єдина утиліта `src/lib/format.ts`,
  ніколи не інлайном.
- Команди: `npm run dev`, `npm run build`, `npm test`, `npm run lint` з теки `frontend/`.
- Коментарі — українською, лише там, де пояснюють *чому*.

- **Автовизначення за складом:** якщо обрано 2 особи — номінації «Соло»
  показуються неактивними з підказкою «Для 2 осіб — Дуети». Пороги:
  1 → Соло, 2 → Дует, 3 → Тріо, 4–7 → Групи, 8–24 → Формейшн, 25+ → Продакшн.
  Це підказка, а не заборона: організатор міг завести нестандартну сітку, тож
  неактивні пункти вмикаються посиланням «Показати всі номінації».

**`ApplyPage`:**
- Один сабміт → один `POST` з масивом `nominationIds`. **Не цикл по запитах.**
- Після успіху — екран підтвердження зі списком створених заявок, наскрізним
  номером учасника і кнопкою «Завантажити треки».
- **Над формою — блок «Ви вже в заявках на цей конкурс»**, якщо такі є.
  Показує заявки, у складі яких є ця людина, включно з поданими тренером

  передивляється, чи її вже не заявили, перш ніж подавати самій (§8.5 бачення).
  Якщо заявок немає — блока немає.
- **Дублікати не блокуються.** Сервер приймає повторну заявку, і клієнт нічого
  не перевіряє й нічого не забороняє. Не додавай попереджень-модалок «ви вже
  заявлені, точно продовжити?»: блок над формою вже все показав, а внесок
  сплачується за обидві заявки.
- Помилка `403` (реєстрація закрита) — банер зверху й заблокований сабміт.

## Фінальна перевірка

- [ ] `npm test` — усі тести зелені.
- [ ] `npm run build` — `tsc -b` і збірка Vite без помилок.
- [ ] `npm run lint` — без помилок.
- [ ] Пройти вручну три наскрізні сценарії:
  1. **Тренер:** реєстрація → ростер → заявка на 3 номінації → завантаження треків → перегляд програми з підсвіткою.
  2. **Організатор:** створення конкурсу → правила → спецкатегорія → формування відділення → перевпорядкування → друк розширеної програми.
  3. **Суддя:** вхід → згорнутий список → аркуш → надсилання → заміна судді → продовження новим суддею.
  4. **Учасник:** реєстрація → прив'язка до свого запису («Це я») → заявка на 2 номінації → трек → програма з підсвіткою своїх виступів → «Мої результати».
  5. **Глядач, без входу:** відкрити конкурс → програма → знайти учасника пошуком за прізвищем → результати. Жодна сторінка цього шляху не має вимагати авторизації.
- [ ] **Перевірити подвійну заявку вручну:** заявити ту саму людину на ту саму номінацію спершу тренером, потім учасником. Обидві мають створитись. Учасник перед подачею бачить блок «Ви вже в заявках» із заявкою тренера; кнопок редагування на ній немає.
- [ ] Перевірити мобільну верстку на 360 px: головна, програма, результати, кабінет судді.
