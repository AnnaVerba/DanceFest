# DanseFest Frontend — таски

**Мета:** інтерфейси ядра змагання — реєстрація з ростером, налаштування конкурсу, конструктор програми, кабінет судді й результати.

**Стек:** React 19, react-router-dom 7, TypeScript, Vite 8, CSS Modules, `fetch`.

**Архітектура:** кожен модуль бекенду має свій файл-клієнт у `src/lib/` за наявним зразком (`lib/nominations.ts`: типізовані інтерфейси, `request<T>`, клас помилки `XxxApiError`). Сторінки в `src/pages/`, багаторазові частини в `src/components/`. Стилі — CSS-модулі поруч із компонентом. **Жодної арифметики часу, кворуму чи місць на клієнті:** усе рахує сервер, клієнт показує.

**Spec:** `docs/superpowers/specs/2026-08-18-danse-fest-technical-vision-design.md`
**Парний план:** `docs/superpowers/plans/2026-08-18-danse-fest-backend.md` — усі ендпоінти визначені там.

**Як читати таск:** `Екран` — що бачить користувач. `Правила` — поведінка, яку не видно з макета. `Готово, коли` — критерії приймання: те, що перевіряється кліком, а не станом коду.

## Глобальні обмеження

- Мова інтерфейсу — **українська**. Жодного англомовного тексту в UI.
- Base URL береться з `src/lib/api.ts` (`API_BASE_URL`), ніколи не хардкодиться в компоненті.
- Кожен екран із завантаженням даних має **три стани**: завантаження, помилка з кнопкою «Спробувати ще раз», порожній стан з поясненням що робити далі.
- Кнопки, що шлють запит, блокуються на час запиту й показують текст стану («Зберігаємо…»), інакше подвійний клік створює дублікат.
- Помилки з сервера показуються **дослівно** — бекенд віддає готові українські повідомлення, вигадувати свої не треба.
- Час — `ГГ:ХХ:СС` (у програмі) або `ГГ:ХХ` (старт відділення), тривалості — `Х:ХХ`. Форматування — єдина утиліта `src/lib/format.ts`, ніколи інлайном.
- Ніяких magic numbers і magic strings: пороги, дебаунси, ліміти — іменовані константи в окремих файлах.
- Коментарі — українською, лише там, де пояснюють *чому*.

## Фаза 1 — Оточення й ролі

### FE-1: Formatting utilities

Єдине місце, де секунди перетворюються на текст. Дублювати форматування по компонентах не можна — програма й друкована версія розійдуться.

**`src/lib/format.ts`:**
```ts
formatClock(secondsFromMidnight) // 32400 → '09:00:00', 32480 → '09:01:20'
formatDuration(seconds)          // 75 → '1:15', 60 → '1:00', 5 → '0:05'
```
Обидві доповнюють нулями зліва; `formatDuration` не показує години, доки тривалість менша за годину.

**Готово, коли:**
- [ ] Час у програмі, у розширеній програмі й у списку треків форматується цією утилітою, а не вручну.

### FE-2: Role-aware registration and route guards

**Екран реєстрації:**
- Вибір ролі — **три картки з поясненням**, а не випадний список: «Організатор — проводжу конкурси», «Керівник — реєструю своїх учасників», «Учасник — реєструюсь сам». Роль `superadmin` у виборі відсутня.
- Під картками — рядок «Щоб просто подивитись програму чи результати, реєструватись не треба», з посиланням на публічний список конкурсів. Акаунт дає впізнавання, а не доступ до перегляду (Р9).
- **Після реєстрації як `participant`** — одразу екран прив'язки до свого запису: кандидати за ПІБ (`GET /persons/candidates`) з кнопкою «Це я» на кожному, і кнопка «Мене ще не заявляли», яка створює нову Особу. Пропустити крок не можна: без прив'язки бекенд віддасть `409` на заявку.

**`RequireRole`:**
```ts
type Role = 'superadmin' | 'organizer' | 'coach' | 'participant';
<RequireRole roles={['organizer','superadmin']}>…</RequireRole>
```
- Немає токена → редірект на `/login` з `state.from`.
- Невідповідна роль → сторінка «Немає доступу» з кнопкою «На головну». **Не мовчазний редірект** — він виглядає як поламане посилання.
- Роль читається з payload збереженого JWT.

**Захищаються:** `/dashboard`, `/competitions/new`, `/competitions/:id/edit`, `/competitions/:id/team`, `/category-templates*` → `organizer | superadmin` (замінити наявний коментар `TODO: обгорнути AuthGuard` у `App.tsx`).

**Готово, коли:**
- [ ] Тренер на маршруті організатора бачить «Немає доступу», а не порожній екран і не редірект.
- [ ] Новий учасник не може дійти до форми заявки, не прив'язавшись до Особи.
- [ ] Гість бачить публічний список конкурсів без входу.

## Фаза 2 — Реєстрація на конкурс

### FE-3: API clients for persons, roster and registrations

Три клієнти в `src/lib/`, кожен за зразком `lib/nominations.ts`, зі своїм класом помилки (`PersonApiError`, `RosterApiError`, `RegistrationApiError`).

**`persons.ts`:** `Person {id, lastName, firstName, middleName, birthDate, city, studioName}`, `PersonCandidate extends Person { score }`, `findCandidates()`, `mergePersons()`.
**`roster.ts`:** `RosterEntry extends Person { lastRegisteredAt }`, `listRoster()`, `removeFromRoster()`.
**`registrations.ts`:** `RegistrationInput {participants[], nominationIds[], routineName?, choreographer?, studioName?, city?, improv?}`, `createRegistration()` → `Registration[]`, `cancelRegistration()` → `{ requiresScheduleRecalculation }`.

**Готово, коли:**
- [ ] Помилка сервера доходить до UI з її статусом і дослівним повідомленням, а не як `Failed to fetch`.

### FE-4: Coach roster page

**Екран (`/roster`, роль `coach`):** список своїх учасників за прізвищем. Рядок: ПІБ, студія, місто, коли востаннє заявляли.

**Правила:**
- **Хрестик навпроти кожного** прибирає з ростера. Перед видаленням — `ConfirmDialog` (наявний `components/admin/ConfirmDialog.tsx`) з текстом: «Прибрати {ПІБ} зі свого списку? Учасник лишиться в системі — це прибере його лише з вашого списку.» Формулювання важливе: тренер має розуміти, що не видаляє дитину назавжди.
- Помилка `409` (є активна заявка) — дослівно в тості (`components/admin/useToasts.ts`), рядок лишається на місці.
- Кнопка «Додати нового» веде на форму заявки з порожнім учасником.
- **Порожній стан:** «Тут з'являться ваші учасники після першої заявки на конкурс» + кнопка «Перейти до конкурсів».

**Готово, коли:**
- [ ] Видалення з ростера питає підтвердження й не видаляє людину з системи.
- [ ] `409` лишає рядок на місці й показує причину.

### FE-5: Multi-nomination registration form

Центральний екран продукту для тренера. Одна дитина виступає 3–7 разів, і вводити дані заново на кожен вихід неприйнятно.

**`ParticipantPicker`:**
- Роль `coach`: ростер списком із чекбоксами + кнопка «Додати нового».
- Роль `participant`: власна Особа підставлена й зафіксована — учасник заявляє лише себе. Один нередагований рядок із ПІБ і наскрізним номером, якщо він уже виданий.
- **Множинний вибір** — той самий компонент обслуговує і соло, і груповий номер.
- Обрані показуються чипами зверху, з хрестиком на кожному. Лічильник «Обрано: 12 осіб» — він же джерело автовизначення номінації.

**`NominationMultiSelect`:**
- Дерево: вікова категорія → ліга → номінації, з чекбоксом на кожній. Пошук по назві звужує дерево.
- Біля кожної номінації — ціна. Знизу липкий підсумок: «Обрано 4 номінації · 1 200 грн».
- **Автовизначення за складом:** обрано 2 особи — «Соло» неактивне з підказкою «Для 2 осіб — Дуети». Пороги: 1 → Соло, 2 → Дует, 3 → Тріо, 4–7 → Групи, 8–24 → Формейшн, 25+ → Продакшн.
- Це **підказка, а не заборона**: організатор міг завести нестандартну сітку, тож неактивні пункти вмикаються посиланням «Показати всі номінації».

**Сторінка заявки:**
- Один сабміт → **один** `POST` з масивом `nominationIds`. Не цикл по запитах.
- Після успіху — екран підтвердження зі списком створених заявок, наскрізним номером і кнопкою «Завантажити треки».
- **Над формою — блок «Ви вже в заявках на цей конкурс»**, якщо такі є: заявки, у складі яких є ця людина, включно з поданими тренером («Соло · Табла — заявив тренер Іваненко О.»). Це те місце, де людина передивляється, чи її вже не заявили, перш ніж подавати самій. Немає заявок — немає блока.
- **Дублікати не блокуються.** Клієнт нічого не перевіряє й не забороняє. Не додавай модалок «ви вже заявлені, точно продовжити?»: блок над формою вже все показав, а внесок сплачується за обидві заявки.
- Помилка `403` (реєстрація закрита) — банер зверху й заблокований сабміт.

**Готово, коли:**
- [ ] Заявка на три номінації відправляється **рівно одним** запитом.
- [ ] Після успіху видно три заявки й наскрізний номер учасника.
- [ ] Блок «Ви вже в заявках» показує, хто подав кожну заявку, і не має кнопок редагування на чужих.
- [ ] Повторна заявка на ту саму номінацію проходить без жодного попередження.
- [ ] Обрано 2 особи → «Соло» неактивне з підказкою, «Показати всі» його вмикає.

### FE-6: Duplicate person hint

**Поведінка (§8.5):**
- Користувач ввів прізвище й ім'я нового учасника і пішов з поля (`onBlur`) → `findCandidates`.
- Є кандидати зі `score >= 60` → під полями ненав'язлива панель: «Схоже, ця людина вже є в системі», список (ПІБ, студія, місто) з кнопкою «Це вона» на кожному.
- «Це вона» підставляє наявний `personId` замість створення нової особи.
- Поруч завжди є «Ні, це інша людина» — ховає панель і більше не показує її для цього вводу.
- **Автоматичного вибору немає ніколи** (Р7). Панель нічого не робить сама.
- Запит не викликається, доки прізвище коротше за 2 символи.

**Готово, коли:**
- [ ] Кандидат зі `score: 80` показується, зі `score: 40` — ні.
- [ ] «Ні, це інша» ховає панель, і повторний `onBlur` її не повертає.

## Фаза 3 — Налаштування конкурсу

### FE-7: Competition rules page

**Екран (`/competitions/:id/rules`)** — чотири блоки з підзаголовками: «Час і паузи», «Доплати за переліміт», «Фінанси», «Відбори».

**Правила:**
- **Усі поля вже заповнені значеннями за замовчуванням** із сервера — організатор може нічого не чіпати й піти. Під заголовком: «Ці налаштування вже мають робочі значення. Змінюйте лише те, що відрізняється у вашому положенні.»
- **Вимикач `surchargesEnabled`** керує видимістю: вимкнений — блок тарифів згортається, а натомість з'являється вибір `timeSource` двома радіо-кнопками: «Рахувати за фактичною тривалістю треків» / «Рахувати за часом із положення». Це прямо з документа: конкурс без доплат має отримати два варіанти.
- `OverlimitTariffs` — таблиця «переліміт до N секунд → M грн» з додаванням і видаленням, рядки автоматично сортуються за `uptoSeconds`. Дублікат `uptoSeconds` підсвічується червоним і блокує збереження.
- `DurationLimits` — таблиця лімітів із вибором номінації або осі (ліга/вік), туру (фінал/півфінал) і тривалості. Ввід приймає і `1:30`, і `90` — обидва дають 90 секунд.
- `coachPercent` — поле у відсотках із підказкою «Один відсоток на весь конкурс. Застосовується до внесків за участь, не до доплат за переліміт.»
- Збереження — `PATCH`, часткове, тост «Правила збережено».
- Якщо в конкурсі вже є сформовані відділення — попередження під кнопкою: «Зміна пауз і лімітів не перерахує вже сформовані відділення автоматично. Перерахувати можна на сторінці програми.»

**Готово, коли:**
- [ ] Вимкнені доплати ховають тарифи й показують вибір способу підрахунку часу.
- [ ] Дублікат порогу тарифу блокує збереження й видно, який саме рядок винен.
- [ ] `1:30` і `90` дають однаковий результат на сервері.

### FE-8: Special category builder with live preview

**Екран — рівно шість кроків із §8.3:**
1. Поле «Назва категорії» («Корона Шехеризади»).
2. Множинний вибір програм зі списку стилів.
3. **Дві радіо-кнопки кількості виходів**, з поясненням під кожною: «Один вихід — усі програми танцюються підряд, без сходження зі сцени» / «Окремий вихід на кожну програму».
4. Множинний вибір вікових категорій і ліг.
5. Поле ціни.
6. **Живий попередній перегляд** — найважливіша частина екрана:
   - один вихід: `Юніори 1 · Перші кроки · Корона Шехеризади`
   - кілька: та сама категорія повторюється по програмах — `… · Корона Шехеризади · Імпровізація межансе`, `… · Корона Шехеризади · Табла`
   Поруч — лічильник «Буде створено 14 номінацій». Без цього перегляду організатор не розуміє, що саме натворить, поки не збереже.

Сабміт шле `POST /competitions/:id/nominations/bulk` (наявний ендпоінт) з готовим набором.

**Готово, коли:**
- [ ] Перемикання на «окремий вихід» множить рядки перегляду на кількість програм.
- [ ] Лічильник завжди дорівнює кількості рядків перегляду.
- [ ] Порожня назва блокує сабміт.

## Фаза 4 — Треки

### FE-9: Track upload with over-limit warnings

**Екран (`/my/performances`, ролі `coach` і `participant`):** одна сторінка на дві ролі — тренер бачить виходи своїх учнів (згруповані за учасником), учасник свої власні. Джерело різне, подання те саме. У рядку: номінація, наскрізний номер, стан треку.

**Правила:**
- Рядки заявок, поданих **не поточним користувачем**, показуються, але лише для перегляду: зона завантаження замінена підписом «Заявив тренер Іваненко О.». Ознака `canEdit` приходить із сервера, клієнт її не обчислює.
- `TrackUploader` — зона перетягування + вибір файлу. Підпис перелічує **усі дозволені формати**, не лише mp3: «MP3, WAV, M4A, AAC, OGG, FLAC, до 50 МБ». Це видима вимога документа замовника.
- Під час завантаження — прогрес у відсотках (через `XMLHttpRequest`: `fetch` не дає прогресу вивантаження).
- Після успіху рядок показує тривалість і **порівняння з лімітом**:
  - у ліміті → зелена позначка «1:28 із 1:30»;
  - переліміт при ввімкнених доплатах → жовтий блок «Перевищення 15 с. Доплата 150 грн» і кнопка «Як оплатити»;
  - переліміт при вимкнених доплатах → сірий блок «Перевищення 15 с. Трек буде зупинено на 1:30» (або «буде відтворено повністю») — **формулювання приходить із сервера**, клієнт не вирішує сам.
- Помилки дослівно: `415` (формат), `413` (розмір), `422` (не читається тривалість), `403` (термін вийшов).
- Імпровізаційні заявки: замість зони — рядок «Трек не потрібен: музику вмикає організатор».
- Повторне завантаження — кнопка «Замінити трек» із підтвердженням, якщо доплата вже оплачена: «Доплату за попередній трек уже сплачено. Заміна перерахує доплату. Продовжити?»

**Готово, коли:**
- [ ] WAV вантажиться без помилки, PDF показує повідомлення сервера про формати.
- [ ] Переліміт із доплатою показує суму, без доплат — що станеться з треком.
- [ ] Імпровізаційна заявка не має зони завантаження.
- [ ] Заміна оплаченого треку питає підтвердження.

## Фаза 5 — Програма фестивалю

### FE-10: Section builder with filtered pool

**Екран (`/competitions/:id/program`) — точно кроки 1–5 із §8.7:**
1. Зверху перемикачі дня і майданчика. Один день і один майданчик — перемикачі приховані.
2. `UnassignedPool` — нерозподілені виходи з **фільтрами за віковою категорією і лігою**, лічильник «Нерозподілено: 47».
3. Кнопка **«Обрати все»** позначає все, що пройшло фільтр (не весь пул). Поруч — «Зняти вибір».
4. Кнопка **«Сформувати відділення»** відкриває модалку з полями «Назва відділення» (передзаповнено «Відділення N») і «Час початку» (`ГГ:ХХ`). Обидва обов'язкові.
5. Після створення сторінка перемальовує відділення з **обчисленим сервером часом** кожної позиції і рядком нагородження в кінці.

**Правила:**
- Помилка `409` (виходи вже розподілені) показує список конфліктних і пропонує «Оновити пул».

### FE-11: Reorder, move and merge program groups

**Правила (§8.7, кроки 6–7):**

- [ ] Нагородження неможливо перетягнути.
- [ ] Помилка `400` відкочує порядок і пояснює, що розклад змінив хтось інший.

## Фаза 9 — Тури

### FE-20: Semifinal control and final qualification

**Правила (§8.12):**

**Готово, коли:**
- [ ] Перші K позначені за замовчуванням, зміна K перепозначає список.
- [ ] Поділене місце на межі позначає обох і пояснює це підписом.
- [ ] Сабміт шле саме той список, який організатор бачить позначеним.

## Фаза 10 — Життєвий цикл і огляд

### FE-21: Competition status bar and days editor

**`StatusBar`** — горизонтальна стрічка етапів угорі сторінки редагування: Чернетка → Опубліковано → Реєстрація відкрита → Реєстрація закрита → Програма сформована → Триває → Завершено. Пройдені зелені, поточний акцентний, майбутні сірі.

**Правила:**
- Кнопка переходу показує **лише наступний дозволений** етап («Опублікувати», «Відкрити реєстрацію», …). Жодного випадного списку статусів — це не поле, а дія.
- Перед переходом — коротке пояснення наслідку в підтвердженні. Для «Закрити реєстрацію»: «Нові заявки більше не прийматимуться. Треки можна буде вантажити далі, до {дата}.»
- Помилка `400` при публікації показує перелік порожніх полів **із посиланнями на них** — клік прокручує до поля.
- Помилка `409` при переході в «Програма сформована» показує лічильник нерозподілених і кнопку «Перейти до програми».
- `DaysEditor` показується **лише якщо конкурс триває більше одного дня**. Для одноденного дні створені автоматично, і поняття не показується взагалі.

**Готово, коли:**
- [ ] Видима лише одна кнопка переходу — на наступний етап.
- [ ] Помилка публікації дає клікабельний перелік незаповнених полів.
- [ ] Одноденний конкурс не показує редактор днів.

### FE-22: Superadmin overview page

**Екран (`/admin`, роль `superadmin`)** — дві вкладки:
- **Конкурси:** назва, організатор, дати, статус (кольоровий чип), кількість заявок, відсуджених номінацій, сума нарахувань. Сортування за датою спадно, пагінація по 25.
- **Керівники:** прізвище й ім'я, місто, студія, телефон, кількість конкурсів і учасників. Пошук по прізвищу та студії з дебаунсом 300 мс.

**Правила:**
- Панель **тільки для читання** — жодних кнопок редагування. Це навмисно: сервер мутацій і не приймає.
- Доступ лише ролі `superadmin` через `RequireRole` (FE-2).

**Готово, коли:**
- [ ] Роль `organizer` бачить «Немає доступу».
- [ ] Пошук шле запит із `?q=` і звужує список.
- [ ] Перемикання вкладок не втрачає введений пошук.

## Фінальна перевірка

- [ ] `npm run build` (`tsc -b` + Vite) і `npm run lint` — без помилок.
- [ ] Наскрізні сценарії вручну:
  1. **Тренер:** реєстрація → ростер → заявка на 3 номінації → завантаження треків → програма з підсвіткою.
  2. **Організатор:** створення конкурсу → правила → спецкатегорія → формування відділення → перевпорядкування → друк розширеної програми.
  3. **Суддя:** вхід → згорнутий список → аркуш → надсилання → заміна судді → продовження новим суддею.
  4. **Учасник:** реєстрація → «Це я» → заявка на 2 номінації → трек → програма з підсвіткою своїх виступів → «Мої результати».
  5. **Глядач, без входу:** конкурс → програма → пошук за прізвищем → результати. Жодна сторінка цього шляху не вимагає авторизації.
- [ ] **Подвійна заявка вручну:** заявити ту саму людину на ту саму номінацію спершу тренером, потім учасником. Обидві створюються; учасник перед подачею бачить блок «Ви вже в заявках» із заявкою тренера, без кнопок редагування на ній.
- [ ] Мобільна верстка на 360 px: головна, програма, результати, кабінет судді.
- [ ] Жоден екран не рахує час, місця чи кворум локально: `grep -rn "pauseSeconds\|quorum" frontend/src --include=*.tsx` показує лише показ значень, не арифметику.
