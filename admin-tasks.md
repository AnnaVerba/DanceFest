# Тренер / керівник

## TASK-21 — Замінити «Тренер» на «Керівник» і додати ознаку «Я керівник»

| Поле | Значення |
|---|---|
| **Тип** | Task |
| **Пріоритет** | Середній |
| **Роль** | Тренер (Керівник) |
| **Компонент** | Frontend (тексти, онбординг) + Backend (поле профілю) |
| **Залежності** | — |

### Опис

Замість «Тренер» має бути «Керівник». У формі «Завершіть профіль» потрібен чекбокс «Я керівник».

### Поточний стан

Скрізь використовується «Тренер» (бейдж ролі, «Ваш тренер», колонки таблиць); в адмінських «Заявках» колонка називається «Хореограф». Чекбокса «Я керівник» немає.

### Очікуваний результат

В інтерфейсі єдина назва «Керівник»; є чекбокс «Я керівник».

> 📷 *Скріншот: онбординг «Завершіть профіль» — блок «Ваш тренер»*

### Технічні нотатки

- Змінити лише відображувані тексти (бажано через єдиний словник або i18n); внутрішню роль у БД (`TRAINER`) можна не перейменовувати.
- Уніфікувати назви колонок «Тренер» / «Хореограф» → «Керівник».
- Чекбокс «Я керівник»: якщо відмічено — приховати поля «Ваш керівник» і записати керівником самого користувача. Зберігати в профілі.
- Помічено на скріншоті: при введенні наявної школи з'являється «Школа з такою назвою вже існує». Варто запропонувати вибрати наявну школу замість блокування (погодити).

### Критерії приймання

- [ ] В інтерфейсі тренера й адмінки скрізь «Керівник».
- [ ] Чекбокс «Я керівник» є, стан зберігається.
- [ ] Якщо відмічено, керівником заявок стає сам користувач.

# Тренер / заявки

## BUG-22 — Фільтрувати вікові категорії відповідно до віку учасника

| Поле | Значення |
|---|---|
| **Тип** | Bug |
| **Пріоритет** | Високий |
| **Роль** | Тренер (Керівник) / Учасник |
| **Компонент** | Frontend (форма заявки) + Backend (валідація) |
| **Залежності** | — |

### Опис

Вік учасника визначено як «25 р. · Молодь 2», але в «Номінаціях за обраними стилями» пропонуються також Молодь 1, Юніори 1 і Юніори 2.

### Кроки відтворення

1. «Подати заявку» → вибрати учасника віком 25 років.
2. Ліга «Вища», стиль «Raks al Sharki».

### Фактичний результат

Список містить номінації всіх вікових категорій.

### Очікуваний результат

Пропонуються лише номінації віку учасника (Молодь 2).

> 📷 *Скріншот: учасник 25 р. (Молодь 2), але пропонуються Молодь 1, Юніори 1, Юніори 2*

### Технічні нотатки

- Фільтрувати номінації за вирахуваною віковою категорією, лігою та стилем.
- Уточнити правило: вік рахується на дату конкурсу чи на дату заявки? Для групи — за найстаршим, середнім чи іншим правилом?
- Backend: відхиляти заявку в несумісну вікову категорію (виняток — організатор або адмін, якщо погоджено).

### Критерії приймання

- [ ] Для учасника «Молодь 2» у списку лише номінації «Молодь 2».
- [ ] Несумісну заявку не можна створити і через API.
- [ ] Для груп діє погоджене правило.

# Тренер / мої учасники

## BUG-23 — Відображати учасників і суми в заявках тренера (керівника)

| Поле | Значення |
|---|---|
| **Тип** | Bug |
| **Пріоритет** | Високий |
| **Роль** | Тренер (Керівник) |
| **Компонент** | Frontend (сторінка «Мої заявки») + Backend (запит) |
| **Залежності** | Пов'язано з TASK-20, BUG-28 |

### Опис

У розділі «Мої заявки» тренера не відображаються учасники (лише «№ учасника»), немає суми по учаснику та загальної.

### Кроки відтворення

1. Увійти як тренер → «Мої заявки».

### Фактичний результат

Колонки ПІБ і вартості немає; таблиця прокручується горизонтально, колонка «Музика» обрізана.

### Очікуваний результат

Видно учасника, вартість кожної заявки, суму по учаснику та загальну.

> 📷 *Скріншот: «Заявки моїх учасників» — немає ПІБ учасника та сум*

### Технічні нотатки

- Додати колонки «Учасник» (ПІБ; для групи — список) і «Вартість»; рядок підсумку по конкурсу та загальний.
- Перевірити запит: в адмінських «Заявках» конкурсу «Шехеризада» є 5 заявок учасниці Висоцької Ульяни з керівником Анастасією Білошкап, але в «Моїх заявках» Анастасії їх немає. Схоже, запит фільтрує за `createdBy` (хто створив), а не за `trainerId`. Заявки, створені організатором (TASK-17), мають бути видні тренеру.
- Адаптувати таблицю, щоб усі колонки вміщалися без горизонтальної прокрутки на десктопі.

### Критерії приймання

- [ ] У кожній заявці видно учасника.
- [ ] Є сума по кожному учаснику та загальна.
- [ ] Тренер бачить усі заявки, де він вказаний керівником, незалежно від того, хто їх створив.
- [ ] Суми збігаються з фінансовим звітом (TASK-20).

# Публічна програма

## TASK-24 — Розділити публічну програму за майданчиками

| Поле | Значення |
|---|---|
| **Тип** | Task |
| **Пріоритет** | Середній |
| **Роль** | Усі користувачі |
| **Компонент** | Frontend (публічна програма) |
| **Залежності** | Залежить від BUG-12, BUG-19 |

### Опис

Програма майданчиків А і Б має відображатися окремими блоками.

### Поточний стан

Програма одним списком без розділення на майданчики.

### Очікуваний результат

Окремі блоки (або вкладки) «Майданчик А» і «Майданчик Б».

> 📷 *Скріншот: публічна програма — блоки «Ваша програма» і «Повна програма», майданчики не розділені*

### Технічні нотатки

- Групувати відділення за `siteId`; для кожного майданчика свій час початку та власні відділення.
- На мобільних — вкладки А / Б, на десктопі — вкладки або дві колонки (погодити).

### Критерії приймання

- [ ] Майданчики А та Б відображаються окремо.
- [ ] У кожному блоці лише його виступи.

## TASK-25 — Зробити відділення програми згортаними; лишити тільки повну програму

| Поле | Значення |
|---|---|
| **Тип** | Task |
| **Пріоритет** | Середній |
| **Роль** | Усі користувачі |
| **Компонент** | Frontend (публічна програма) |
| **Залежності** | — |

### Опис

Програма має згортатися по відділеннях, щоб користувач відкривав лише своє відділення, а не гортав усю програму. Замовник також просить лишити тільки повну програму (без окремого блоку «Ваша програма»).

### Поточний стан

Програма відкрита повністю; є окремий блок «Ваша програма».

### Очікуваний результат

Лише повна програма, відділення згортаються та розгортаються.

### Технічні нотатки

- Акордеон по відділеннях; за замовчуванням згорнуті (або відкрите поточне чи найближче — погодити).
- Кнопки «Згорнути всі» / «Розгорнути всі» і швидкий перехід до відділення.
- Прибрати блок «Ваша програма». Позначку «Ваш виступ» у повній програмі можна лишити (погодити).
- Пошук за прізвищем або номером має розгортати відділення зі знайденим виступом.

### Критерії приймання

- [ ] Кожне відділення згортається й розгортається.
- [ ] Блоку «Ваша програма» немає.
- [ ] Повна програма доступна, пошук працює.

## TASK-26 — Спростити та доповнити дані в публічній програмі

| Поле | Значення |
|---|---|
| **Тип** | Task |
| **Пріоритет** | Середній |
| **Роль** | Усі користувачі |
| **Компонент** | Frontend (публічна програма) + API |
| **Залежності** | Залежить від BUG-18 |

### Опис

У публічній програмі додати номер категорії, лишити тільки час початку та кінця відділення, показувати студію і через кому керівника, наприклад: «Шехеризада, тренер Білошкап Анастасія».

### Поточний стан

Біля кожного виступу й блоку є точний час із секундами (09:00:00, 09:01:50); студії немає, виводиться лише тренер.

### Очікуваний результат

Номер категорії; у заголовку відділення — лише «початок – кінець» (ГГ:ХХ); у рядку виступу — «Студія, керівник ПІБ».

### Технічні нотатки

- Прибрати час окремих виступів і блоків у публічному режимі; у заголовку відділення показувати «09:00 – 10:30».
- Формат рядка: `{студія}, {роль} {ПІБ}`. Якщо студії немає — лише керівник.
- Слово «тренер» чи «керівник» — відповідно до [TASK-21](#task-21--замінити-тренер-на-керівник-і-додати-ознаку-я-керівник).

### Критерії приймання

- [ ] Відображається номер категорії.
- [ ] У відділення вказано лише час початку та кінця.
- [ ] Студія й керівник у погодженому форматі.
- [ ] Зайвого службового часу немає.

# Безпека / права доступу

## BUG-27 — Заборонити доступ до адмінки чужого конкурсу до підтвердження заявки на організатора

| Поле | Значення |
|---|---|
| **Тип** | Bug (безпека) |
| **Пріоритет** | Критичний |
| **Роль** | Користувач із непідтвердженою заявкою на організатора |
| **Компонент** | Backend (авторизація) + Frontend (вкладки) |
| **Залежності** | — |

### Опис

Після подачі заявки на організатора, поки вона не підтверджена, користувачу відображаються адмін-вкладки чужого конкурсу (Номінації, Майданчики, Таймінги). Редагувати їх не можна, але доступу не повинно бути взагалі.

### Кроки відтворення

1. Користувач із роллю «Тренер» подає заявку на організатора (не підтверджена).
2. Відкрити чужий конкурс (наприклад, «Шехеризада»).

### Фактичний результат

Видно вкладки «Майданчики» й «Таймінги» з налаштуваннями конкурсу.

### Очікуваний результат

Службові вкладки видно лише організатору цього конкурсу та адміну.

> 📷 *Скріншот: роль «Тренер» — доступна вкладка «Таймінги» чужого конкурсу*
>
> 📷 *Скріншот: роль «Тренер» — доступна вкладка «Майданчики»*

### Технічні нотатки

- Статус заявки на організатора `PENDING` не дає жодних організаторських прав.
- Права на службові вкладки — лише якщо `user.role === ADMIN` або користувач — затверджений організатор саме цього конкурсу.
- Обов'язкова перевірка на бекенді для всіх службових ендпоінтів (майданчики, таймінги, заявки, доплати, редагування програми) — 403 для сторонніх. Приховування вкладок на фронті недостатньо.
- Погодити, які вкладки публічні (ймовірно «Деталі», «Номінації» для подачі заявки, «Програма» після публікації).

### Критерії приймання

- [ ] Користувач із непідтвердженою заявкою не бачить службових вкладок чужого конкурсу.
- [ ] Прямий запит до службових API повертає 403.
- [ ] Після підтвердження організатор має доступ лише до своїх конкурсів.
- [ ] Перевірено для ролей: гість, учасник, тренер, організатор (pending), організатор іншого конкурсу, організатор цього конкурсу, адмін.
